# Resona

Приложение студии вокала: расписание, абонементы, дневник ученика, теория,
упражнения, тюнер и личная переписка с педагогом. React + TypeScript + Vite.

## Два режима

Приложение живёт в одном из двух режимов, и выбирает его наличие файла `.env`.

**Демо.** Ключей нет — данные лежат в `localStorage` этого браузера, роль
переключается тумблером в углу, ученики и уроки взяты из `src/data.ts`. Годится,
чтобы показать приложение, но не годится для работы: у педагога и ученика будут
две независимые копии, которые друг о друге не знают.

**Сервер.** Ключи есть — данные в Postgres, вход по почте и паролю, роль задана
аккаунтом. Заявка на перенос от ученика доходит до педагога, сообщения видны обеим
сторонам, изменения приезжают на другое устройство без перезагрузки.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm run dev:https  # то же по https — нужно для микрофона на телефоне
```

Тюнеру нужен доступ к микрофону, а его браузер даёт только в защищённом
контексте. На компьютере `localhost` таким считается, с телефона по локальной сети
— нет, поэтому для него `dev:https`. Сертификат самоподписанный: браузер один раз
предупредит, надо согласиться.

## Подключение сервера

1. Создайте проект на [supabase.com](https://supabase.com) (бесплатного плана
   хватает с запасом) и запомните пароль базы.
2. Залейте схему — см. «Как залить схему» ниже. Она создаёт таблицы, политики
   доступа и функции, а сид добавляет кабинеты, рабочие окна и список учеников.
3. В **Authentication → Providers → Email** выключите *Confirm email*: студии на
   десяток человек подтверждение почты только мешает, а письма Supabase любит
   складывать в спам.
4. Скопируйте `.env.example` в `.env` и подставьте `Project URL` и ключ `anon`
   из **Project Settings → API**.
5. Перезапустите `npm run dev`.

### Как залить схему

Три способа, любой из них делает одно и то же. Разница только в том, что ваша
сеть согласна пропустить.

**По HTTPS.** Создайте личный токен в **Account → Access Tokens**, положите его в
`.env` как `SUPABASE_ACCESS_TOKEN`, и:

```bash
npm run db:apply -- --seed          # на пустом проекте
npm run db:apply -- --reset --seed  # начисто, снеся прежнюю схему
```

**Напрямую.** Быстрее и без токена, но нужен доступ к протоколу Postgres. Строку
подключения возьмите в кнопке **Connect** сверху, вкладка **Session pooler**, и
положите её в `.env` как `SUPABASE_DB_URL`. Дальше те же команды.

Прямое подключение работает не везде. Хост `db.<ref>.supabase.co` у новых
проектов существует только в IPv6, так что без IPv6-связности до него не дойти —
остаётся пулер, но его адрес содержит регион проекта, а регион нигде в публичном
API не написан. Хуже того, протокол Postgres на 5432 и 6543 иногда фильтруют по
пути наружу: соединение поднимается, несколько запросов проходят, а потом оно
молча умирает по таймауту. Если видите `Connection terminated unexpectedly` в
одном и том же месте — дело не в базе, идите по HTTPS.

**Руками.** Если не проходит ни то, ни другое:

```bash
npm run db:print   # склеит supabase/setup.sql
```

Вставьте `supabase/setup.sql` целиком в **SQL Editor** проекта и запустите. Файл
самодостаточен и заканчивается запросом, который вернёт коды приглашений.

### Кто становится педагогом

Первый зарегистрировавшийся аккаунт получает роль педагога — регистрироваться
первой должна Адель. Все следующие входят учениками и до ввода кода не видят
ничего: карточка ученика привязывается к аккаунту кодом из шести знаков, который
педагог видит в карточке и может скопировать вместе с текстом приглашения.

### Что запрещено ученику

Ученик не пишет в таблицы напрямую. Всё, что ему разрешено, — это функции базы:
отметить домашнее задание, записать минуты практики, попросить перенос, отправить
сообщение и отзыв. Поэтому дописать себе занятий в абонемент или закрыть чужой урок
из консоли браузера нельзя. Остальное закрывают политики RLS: чужие карточки,
дневники и переписку ученик не получит, даже если запросит их напрямую.

Правило переноса за 12 часов проверяется в самой базе, а не только в интерфейсе.
Счётчик абонемента там же: статус урока меняет остаток через триггер, поэтому два
устройства не разойдутся в подсчёте.

## Выкладка

Сайт живёт на GitHub Pages: <https://riabinovpa-lab.github.io/resona/>

```bash
npm run deploy   # соберёт и обновит ветку gh-pages
```

Cloudflare Pages не подошёл, хотя выкладка на него прошла успешно: домены
`*.pages.dev` в России блокируют по имени в TLS-рукопожатии, и сайт открывался
только через VPN. Со стороны это выглядит не как отказ сервера, а как обрыв на
подключении — `curl` возвращает ошибку TLS, не дождавшись ответа. У `github.io`
и у Supabase такой беды нет, поэтому сборка переехала сюда.

Pages отдаёт сайт из подпапки с именем репозитория, поэтому в `vite.config.ts`
для сборки задан `base`. Переименуете репозиторий — поправьте и его, иначе
страница откроется пустой: файлы будут искаться в корне домена.

## Структура

```
src/
  cloud/        запросы к Postgres: преобразование строк, операции, реалтайм
  components/   каркас, иконки, тюнер, перехват ошибок
  lib/          формат дат и денег, расчёт свободных слотов, определение высоты тона
  screens/      экраны приложения
  data.ts       демо-данные и справочники: прайс, теория, упражнения
  store.tsx     состояние и все действия, общие для обоих режимов
supabase/
  migrations/   схема, политики, функции
  seed.sql      кабинеты, рабочие окна, список учеников
```

## Проверки

```bash
npm run lint
npm run build
npm run check:db     # схема и правила доступа на настоящем Postgres
npm run check:live   # то же на боевом проекте, но только на пустом
```

`check:db` поднимает Postgres в WASM, подменяет заглушками часть Supabase
(схему `auth`, роли, `auth.uid()`), применяет миграцию и сид, а затем проверяет
именно правила: что ученик видит только своё, не может дописать себе занятий и
закрыть урок, что перенос за 12 часов отклоняется, а счётчик абонемента сходится
при переносе, пропуске и удалении урока. Гонять до заливки схемы в боевую базу.

`check:live` проверяет то, чего на локальном Postgres не видно: что триггер на
регистрацию выдаёт роли, что права через PostgREST выданы, что вид занятости
нельзя использовать для правки чужих уроков. Он заводит два аккаунта и удаляет
их за собой, но роль педагога достаётся первому зарегистрировавшемуся — поэтому
на проекте, где уже есть аккаунты, тест отказывается запускаться.

Права на таблицы выдаёт сама миграция, а не настройки проекта. Раньше их
дописывал только `check:db`, из-за чего тест проходил, а в боевой базе роль
`authenticated` оставалась без доступа к таблицам. Если правишь права —
проверяй `check:live`, локальный прогон такое пропускает.

### Обрывы связи

Соединение с Supabase иногда умирает посередине ответа: запрос не получает
отказа, а обрывается или молча висит. Поэтому клиент ходит через свой `fetch` со
сроком ожидания и повтором — но повторяет только чтения. Повторить запись значит
рискнуть отправить сообщение дважды, а это хуже, чем показать ошибку.
